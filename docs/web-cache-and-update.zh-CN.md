# 网页缓存与版本更新

## 行为

- Docker 一体容器的网页及管理端入口文件返回 `Cache-Control: no-store, no-cache, must-revalidate`。API、WebSocket 路由维持原行为。
- `/assets/*` 单独提供文件服务。部署后已经不存在的脚本返回 404，不再误返回 SPA 的 HTML。
- 每次 Web 生产构建生成独立 `web-build.json`，并把同一构建标识写入 JavaScript。标识不依赖服务端版本号，因此同版本重新部署也能被发现。
- 已打开网页在首次加载、重新获得焦点、恢复可见及每 60 秒检查一次构建标识，请求禁用缓存并增加查询参数。隐藏页面暂停检查，离线、超时、404 和非法响应不触发更新提示。
- 发现新构建，或 Vite 动态资源加载失败时显示刷新按钮。点击后保留当前路由和查询参数，追加缓存绕过参数。不会自动刷新或循环重试，避免中断正在进行的语音/直播。

## 部署与验证

这些改动需要部署新的 Web 产物和一体容器 Caddy 配置；单独部署 Web 的用户应在静态服务器配置相同的入口缓存策略，反向代理/CDN 也不能覆盖该策略或强制缓存 `web-build.json`。

1. 查询 `/` 和 `/index.html` 响应头，确认入口 `Cache-Control`。
2. 打开网页，发布新构建后切回标签页，应显示刷新提示；刷新后提示消失。
3. 请求不存在的 `/assets/missing.js`，应为 404，不能返回 HTML。
4. `web-build.json` 的 `buildId` 应与该构建 JS 内的标识匹配，部署时同时替换整套产物。

旧版网页没有更新检测逻辑，第一次需要用户手动刷新。遇到更新后语音异常，可先 Ctrl+F5，或在访客窗口访问同一 HTTPS 地址；此操作不清除登录数据。若仍出现 `RTCPeerConnection is not a constructor`，须检查浏览器实际构造能力和错误堆栈。缓存机制修复不等于已经确认该异常的根因。

回滚时同时回滚网页完整产物与服务器配置。旧服务器没有构建标识时，新网页会忽略该响应并继续工作。

## 本轮验证

Web 类型检查、lint、生产构建和更新检测单元测试通过；使用实际 Edge 验证新构建提示、手动刷新和资源失败提示。NAS 当前 Caddy 配置解析 dry-run 通过，未应用或重载线上配置。

参考：[Vite 6 生产构建与资源加载错误](https://v6.vite.dev/guide/build)。
