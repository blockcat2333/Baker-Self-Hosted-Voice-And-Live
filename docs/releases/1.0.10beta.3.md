# Baker 1.0.10beta.3

## Summary

Baker 1.0.10beta.3 is a server/all-in-one beta that adds a persistent update proxy setting in the admin panel. The proxy is scoped to Baker update metadata requests so deployments that need a proxy for GitHub or Docker Hub metadata can still check available versions without affecting public IP automation.

## Changes

- Added **Server Updates -> Update Proxy** in the admin panel.
- Added `GET /v1/admin/updates/proxy` and `PATCH /v1/admin/updates/proxy`.
- Stored update proxy settings in `/var/lib/baker/runtime/update-proxy.json`.
- Used the saved HTTP/HTTPS proxy for DockerHub tag discovery and GitHub release metadata fetches.
- Kept Public IP Automation on direct fetch so detected TURN/SFU media IPs still reflect the server's real public address.
- Passed the update proxy URL to update-helper as helper-only configuration and kept it out of replacement container runtime env.
- Documented that Docker image pulls are performed by the host Docker daemon and still require Docker daemon proxy or mirror configuration when registry access fails.
- Updated release tooling and update discovery to recognize dotted beta labels such as `1.0.10beta.3`.

## Upgrade Notes

- Public all-in-one deployments should use `blockcat233/baker:1.0.10beta.3` or `latest`.
- If version checks fail because the server cannot reach GitHub or Docker Hub metadata, save an HTTP/HTTPS proxy in the admin panel before checking versions.
- If image pulling still fails during update, configure the Docker daemon proxy or a registry mirror on the Docker host; Baker's update proxy does not change host Docker daemon networking.
- Do not use the update proxy for public IP automation. Public IP Automation intentionally detects the server's direct public IP.
