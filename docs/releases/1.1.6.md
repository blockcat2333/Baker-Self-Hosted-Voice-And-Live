# Baker 1.1.6

## Summary

Baker 1.1.6 fixes livestream publishing while another stream is being watched,
enforces the selected video codec without silent fallback, and adds end-to-end
SFU diagnostics that separate sender, uplink, server, downlink, and decoder
problems.

## Livestream fixes

- Keeps one share-dialog host mounted independently from the stream dashboard,
  so a viewer can start their own stream without ending the watched stream.
- Treats H.264, VP8, VP9, and AV1 as strict choices in both P2P and SFU modes.
- Verifies the actual SFU Producer codec and rolls back `stream.start` if setup
  fails, preventing ghost publications.
- Rejects viewers that cannot decode the broadcaster's selected codec instead
  of changing the broadcaster codec.

## Diagnostics

- Shows requested and actual codecs plus detected hardware/software acceleration.
- Reports sender capture/encode, SFU ingress, SFU egress/worker, and receiver
  network/decode metrics in the live details panel.
- Produces a conservative initial diagnosis only after two matching samples;
  samples older than six seconds are treated as insufficient.
- Keeps diagnostic samples in Gateway memory only. No migration or telemetry
  persistence is introduced.
- Updates Fastify, fast-uri, and js-yaml to patched compatible releases; the
  production dependency audit reports no known vulnerabilities.
