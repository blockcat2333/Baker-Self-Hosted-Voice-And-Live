# Baker 1.0.10

## Summary

Baker 1.0.10 is a stable server/all-in-one release that promotes the 1.0.10 beta line to a formal release. It includes public IP automation for TURN/SFU media addresses, runtime media address precedence fixes for all-in-one deployments, and the admin update proxy setting for version discovery on restricted networks.

## Changes

- Promoted the server release line to stable public label `1.0.10`.
- Kept all-in-one public IP automation for managed TURN/SFU media addresses.
- Kept `runtime.env` authoritative for dynamic media public addresses after first initialization:
  - `TURN_EXTERNAL_IP`
  - `TURN_URLS`
  - `SFU_ANNOUNCED_IP`
- Kept admin **Server Updates -> Update Proxy** for DockerHub/GitHub metadata requests.
- Kept public IP automation on direct fetch so detected media IPs still reflect the server's real public address.
- Updated English and Chinese deployment docs to pin `blockcat233/baker:1.0.10`.
- Reset the matching desktop/client line to `1.0.10a`.

## Upgrade Notes

- Public all-in-one deployments should use `blockcat233/baker:1.0.10` or `latest`.
- For dynamic public IP environments, keep Public IP Automation enabled in the admin runtime panel after TURN/SFU configuration is correct.
- If version checks fail because the server cannot reach GitHub or Docker Hub metadata, save an HTTP/HTTPS proxy in **Server Updates -> Update Proxy** before checking versions.
- Docker image pulls are still performed by the host Docker daemon. If image download fails during update, configure the Docker daemon proxy or a registry mirror on the Docker host.
