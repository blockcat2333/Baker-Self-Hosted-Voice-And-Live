# Baker 1.0.10beta2

## Summary

Baker 1.0.10beta2 is a server/all-in-one beta that fixes runtime media address precedence after public IP changes. The all-in-one image now treats `runtime.env` as authoritative for dynamic TURN/SFU public media addresses after first initialization, preventing stale Docker env values from re-breaking voice and livestream media after Media/TURN restarts.

## Fixes

- Fixed stale Docker env values overriding updated runtime media addresses after service restart:
  - `TURN_EXTERNAL_IP`
  - `TURN_URLS`
  - `SFU_ANNOUNCED_IP`
- Kept Docker env compatibility for first-run bootstrap, then made `/var/lib/baker/runtime/runtime.env` the source of truth for those dynamic media addresses.
- Moved TURN URL auto-generation into the shared runtime shell helper so Media and TURN derive URLs from the current runtime IP after stale env values are cleared.
- Added regression coverage for Node service entrypoint and all-in-one shell precedence behavior.
- Updated DockerHub update discovery and release workflow tag guards to support compact beta labels with numeric suffixes, such as `1.0.10beta2`.

## Upgrade Notes

- Public all-in-one deployments should use `blockcat233/baker:1.0.10beta2` or `latest`.
- Servers still running `1.0.10beta` may not discover the compact `1.0.10beta2` tag because that version only accepted `beta` without a numeric suffix. In that case, choose the compatibility tag `1.0.10-beta.2` from the update dropdown; it runs the same beta2 build and reports `1.0.10beta2` after upgrading.
- After the first bootstrap, update TURN/SFU public media addresses through the admin runtime settings, Public IP Automation, or `/var/lib/baker/runtime/runtime.env`; do not rely on old Docker env values to keep changing them.
- If voice still fails after upgrading, verify that the running Media process and `turnserver --external-ip` both use the current public IP, and confirm the published SFU/TURN port ranges are reachable.
