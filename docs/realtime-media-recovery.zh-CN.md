# 实时媒体恢复运维指南

## 适用范围

本文适用于 Baker 服务端 `1.1.4`、Baker Desktop `1.1.4a`，以及
`blockcat233/baker:1.1.4` all-in-one 镜像内置的 Web 客户端。内容包括
Gateway、P2P、SFU、语音、直播和共享音乐的短暂故障恢复。它不能替代正确的
HTTPS、TURN、SFU 端口、DNS、反向代理或区域媒体配置。

## 1.1.4 的变化

- 客户端统一跟踪 Gateway、语音、直播发布/观看、音乐发布/收听的恢复事件。
- 自动重试使用指数退避和 20% 抖动，上限 30 秒；基准间隔依次为
  1、2、4、8、16、30 秒。
- 连续失败 5 次后，界面会显示事件类型、最后错误、重试次数、立即重试和
  放弃按钮；在用户放弃或恢复成功前，后台仍会继续自动重试。
- Gateway 能识别握手超时和半开连接。客户端连续缺少 3 个 Pong 时重连；
  服务端连续 6 次心跳未响应时清理旧连接。
- 1.1.4 服务端新增经过认证的 `media.session.reconnect` 命令。Gateway 会
  检查调用者、连接和当前逻辑媒体会话的所有权，在不移除频道成员关系或发布
  意图的情况下重建媒体传输。
- `media.session.restarted` 会通知相关客户端为指定语音、直播或音乐会话重建
  传输，而不是清空整个房间状态。
- 语音恢复保留麦克风轨道、静音状态、音量和目标频道；仅更换故障传输时不会
  再次申请麦克风权限。
- 直播和音乐恢复会保留发布与收听意图。已经由用户或系统终止的屏幕采集轨道
  属于不可重试状态，必须由用户重新选择采集源。
- SFU 优先公告 H.264，同时在浏览器和 mediasoup worker 能协商时支持 VP8、
  VP9 和 AV1。P2P 与 SFU 发送端都会应用选择的编码、码率、帧率和降级策略。
- SFU 观看端增加接收码率、编码、分辨率、帧率、丢包、抖动和丢帧统计。
- 说话检测每 50 毫秒采样，1 次达到开启阈值即激活，连续 5 次低于关闭阈值
  后释放，并使用不同的开/关阈值减少闪烁。

## 恢复协议

`media.session.reconnect` 携带当前会话描述。成功响应包含选定媒体模式、ICE
服务器、新会话描述，以及 SFU 模式所需的路由信息。Gateway 会拒绝未认证、
已过期、属于其他用户，或已经不由当前连接持有的会话。

服务端重建传输时保留逻辑房间状态。语音用户仍在频道成员列表中；直播或音乐
发布仍可被发现。其他参与者收到 `media.session.restarted` 后，只重建对应会话。

恢复操作带有代际保护：已经取消的旧异步任务即使稍后完成，也不能覆盖新会话；
同一个事件的重复恢复请求会被合并。

## 版本兼容性

| 客户端            | 服务端       | 行为                                                                        |
| ----------------- | ------------ | --------------------------------------------------------------------------- |
| 1.1.4 Web/Desktop | 1.1.4        | 原地重建媒体会话，并保留用户意图                                            |
| 1.1.4 Web/Desktop | 1.1.3 或更旧 | 客户端识别不支持的新命令，并在已实现的位置回退到原有离开/重进或重新发布流程 |
| 1.1.3 或更旧      | 1.1.4        | 原有命令仍可使用，但旧客户端不会启用新恢复协议                              |

更换 all-in-one 镜像会同时升级服务端和 Web 客户端；已安装的 Desktop 需要
单独升级。混合版本可以继续使用，但完整恢复能力需要 1.1.4 客户端与服务端配套。

## Desktop 多服务器管理

Baker Desktop 可以保存、编辑、删除、探测和切换多个 Baker 服务器。提交切换
前会同时检查目标 `/health`、公开服务器身份和 Gateway WebSocket；验证失败时
继续保留当前服务器。并发切换有代际保护，较晚返回的旧请求不能选中错误服务器。

服务器注册表位于 Electron 用户数据目录的 `server.json`。原单服务器配置会
自动迁移为 schema 2。服务器记录只保存地址和显示信息，不保存认证密钥。

登录会话按服务器 ID 隔离。只有 Electron `safeStorage` 可用时，才会加密写入
`server-sessions.json`；没有操作系统加密能力时仅保存在内存，重启应用后需要
重新登录。不要把这两个文件作为跨 Windows 用户迁移凭据的方式。

## 升级步骤

1. 备份持久化 `/var/lib/baker`，记录当前固定镜像标签、端口、挂载和环境变量。
2. 执行 `supervisorctl status`，确认 PostgreSQL、Redis、API、Gateway、Media、
   Caddy 和已启用的 TURN 在升级前健康。
3. 拉取 `blockcat233/baker:1.1.4`，或使用经过认证的管理后台一键更新。需要可
   确定回滚时，不要部署 `latest`。
4. 保留 `/var/lib/baker`、`/var/run/docker.sock`、重启策略和全部
   TURN/SFU/HTTPS 端口映射。
5. 等待 Docker 健康状态正常，确认 `/health` 返回 `1.1.4`，并检查
   `/v1/meta/public-config` 的媒体模式符合预期。
6. 把 Windows 客户端升级到 `1.1.4a`。

1.1.4 不需要手工数据库迁移或清空数据。镜像升级时绝不能删除数据卷。

## 验证矩阵

使用两个登录用户测试；双区域部署需要从每个公网域名分别重复：

1. 加入同一个语音频道，切换静音，检查成员列表和说话指示器。
2. 中断客户端网络至少 20 秒后恢复，确认 Gateway 和语音自动恢复，没有重复
   用户，也没有再次弹出麦克风权限。
3. 发起直播并调整质量、编码、码率和帧率，确认发送端和接收端统计反映实际
   协商结果。
4. 分别中断观看端和发布端，确认网络恢复后观看/发布意图能够恢复。
5. 发起共享音乐，分别中断两端，确认监听音量和发布状态保留。
6. 从浏览器或系统采集控件主动结束屏幕分享，确认 Baker 不会无限重试已结束轨道。
7. SFU 模式下确认浏览器选中的远端候选地址和端口属于当前域名对应的公告地址
   与已开放 RTC 范围，并从严格 NAT 网络验证 TURN 回退。

## 故障处理

恢复连续失败 5 次并弹出提示时，先记录事件类型和完整最后错误，再点击立即重试。
然后按顺序检查：

1. `/health`、容器健康状态和 `supervisorctl status`。
2. 浏览器 HTTPS 信任、WebSocket 升级和反向代理超时。
3. Gateway 日志中的认证、心跳、所有权或过期会话拒绝。
4. Media 日志中的 router、transport、producer、consumer、ICE 或 DTLS 错误。
5. 公网 TURN/SFU 的 TCP、UDP 可达性，以及浏览器实际收到的公告端口。
6. 多域名走不同媒体路径时，检查 `MEDIA_REGION_PROFILES` 的 Host 匹配。

网页能打开不代表媒体链路可用。HTTPS、WSS、TURN 和 SFU RTC 候选是相互独立
的网络路径，必须分别验证。

## 回滚

使用之前的固定镜像、同一个 `/var/lib/baker`、相同环境变量和端口重新创建容器。
需要回滚 Desktop 时，卸载当前版本并安装匹配的字母后缀版本。除非问题已经定位
到注册表，否则保留 Electron 用户数据目录；删除它会退出登录并清空服务器列表。

回滚后重新验证健康状态、语音、直播、音乐和每个区域路由。旧版本不具备 1.1.4
的原地媒体恢复协议。

## 安全边界

- 不得把 TURN 密码、DNS API Key、管理员密码或访问令牌放入 Issue、诊断包、
  截图或仓库文件。
- 浏览器媒体权限和认证 WebSocket 必须使用 HTTPS/WSS。
- Docker socket 等同主机级管理能力，应只提供给受信任的 all-in-one 容器。
- DNS 凭据使用最小权限，证书状态持久化到 Baker 数据卷。
- 公网只开放 Web 和必需媒体端口，管理后台保持内网访问。
