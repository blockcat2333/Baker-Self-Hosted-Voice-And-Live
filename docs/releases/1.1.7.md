# Baker 1.1.7

## Summary

Baker 1.1.7 fixes the remaining web-only gate that could swallow the start-stream
action while another stream was being watched. It also expands SFU diagnostics so
bitrate loss can be located between the sender, SFU ingress, SFU egress, and the
viewer instead of being reported as one ambiguous network problem.

## Livestream fixes

- The share dialog has one explicit host in `ChatShell` and no longer depends on
  voice connection state after the user opens it.
- A guild member may start a stream from an opened voice channel without joining
  voice or requesting microphone access.
- The selected channel is carried into the dialog explicitly, and every blocked
  start action shows a reason.
- Publish and watch runtimes remain independent; stopping either direction does
  not tear down the other.
- Strict H.264, VP8, VP9, and AV1 negotiation and rollback behavior from 1.1.6 is
  retained.

## SFU diagnostics

- The popup always shows a four-leg bitrate summary and initial fault boundary.
- The main details view adds a per-stream selector plus 60 seconds of in-memory
  bitrate history on one shared scale.
- Sender and receiver reports include available bandwidth, target bitrate,
  encode/decode/presented frame rates, codec implementation, acceleration state,
  retransmission counters, and privacy-safe ICE path types.
- SFU reports include transport ICE/DTLS state, protocol, per-window counters,
  worker CPU, and a byte-delta bitrate fallback.
- A low bitrate on a static image is not treated as a fault unless CPU, bandwidth,
  loss, delay, frame backlog, or freeze evidence is also present.

Browser WebRTC APIs still choose the hardware or software codec implementation.
Baker reports the implementation and power-efficiency signal when Chromium
provides them; it does not offer a force-hardware/force-software switch that the
browser cannot reliably enforce.

## Privacy and upgrade

- Diagnostic history is process/browser memory only and is cleared with the
  livestream session. No database migration or persistent telemetry was added.
