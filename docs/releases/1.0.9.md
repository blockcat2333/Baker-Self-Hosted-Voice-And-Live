# Baker 1.0.9

## Summary

Baker 1.0.9 pairs the public IP automation work with client-side voice media failure handling. If a stale public IP or unreachable TURN/SFU media path prevents audio from being established, the client now exits the broken voice session and shows a localized connection error instead of appearing connected with no sound.

## Changes

- Voice P2P media failures now become a terminal `connection_error` when every remote media path in the current session remains failed or unestablished past the existing timeout window.
- Voice SFU sessions now observe mediasoup send/recv transport connection state and feed failed/disconnected transport states into the same terminal error path.
- Voice cleanup now best-effort sends `voice.leave`, closes local mic/WebRTC/SFU/audio resources, clears `channelId`, and renders the voice error panel.
- Multi-user rooms keep the session active when at least one remote audio path is still working; only the failed path is surfaced as a connection warning.
- `connection_error` is now mapped to the existing localized `voice.error_connection_issue` copy.
- SFU media statistics display is fixed for voice and livestream diagnostics.
- Release metadata was bumped to server `1.0.9` and desktop/client label `1.0.9a`.

## Deployment Notes

- No database migration is required.
- Existing public IP automation settings are unchanged.
- Operators should still ensure HTTPS, published media ports, TURN credentials, and SFU announced IP settings are correct for their deployment.
- If the public IP changes before the server-side automation catches up, affected clients should now see a voice connection error instead of remaining silently connected to a dead media session.
