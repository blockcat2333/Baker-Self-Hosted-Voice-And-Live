# Baker 1.1.4

## Summary

Baker 1.1.4 hardens realtime communication across temporary network, Gateway,
P2P, and SFU failures. It adds an authenticated media-session restart protocol,
preserves active voice/stream/music intent during recovery, improves media
telemetry and codec control, and adds race-safe multi-server management to the
Electron client.

## Realtime Recovery

- Added `media.session.reconnect` and `media.session.restarted` protocol data.
- Rebuilds transport state without removing logical voice membership or active
  stream/music publication state.
- Preserves microphone tracks, mute state, volume, voice channel, stream
  publication/viewing, and music publication/listening intent.
- Uses a unified exponential-backoff recovery coordinator with jitter, visible
  escalation after five failures, immediate retry, and explicit abandon.
- Detects Gateway handshake timeout and half-open sockets and prevents stale
  asynchronous recovery from overwriting a newer session.
- Falls back to the legacy rejoin/republish paths when a 1.1.4 client connects
  to a server that does not support the new command.

## Media Quality And Telemetry

- Added H.264-first SFU codec negotiation with VP8, VP9, and AV1 capability.
- Applies codec preference, maximum bitrate, maximum frame rate, and balanced
  degradation behavior to P2P and SFU senders.
- Added SFU receiver statistics for livestream viewers.
- Tuned speaking detection with 50 ms samples, fast attack, delayed release,
  and hysteresis.
- Treats user-ended screen capture as non-retryable instead of repeatedly
  reopening a dead track.

## Desktop

- Added a multi-server registry with add, edit, remove, availability, and
  active-server controls.
- Validates API health, server identity, and Gateway WebSocket before switching.
- Migrates legacy single-server configuration to registry schema 2.
- Isolates auth sessions by server and persists them only through Electron
  `safeStorage`; unsupported environments use memory-only sessions.
- Guards concurrent server switches and session writes against races.

## Upgrade And Compatibility

- No manual database migration is required.
- Replace the image while preserving `/var/lib/baker`, all mounts, environment,
  and published TURN/SFU/HTTPS ports.
- A matching 1.1.4 Web/Desktop client is required for the complete in-place
  recovery protocol. Older clients remain compatible with existing commands.
