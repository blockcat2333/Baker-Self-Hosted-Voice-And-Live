# Baker 1.1.3

## Summary

Baker 1.1.3 adds an optional, renewable HTTPS entrypoint to the all-in-one Supervisor image for deployments that use Aliyun DNS and expose Baker through a nonstandard FRP TCP port.

## Changes

- Builds Caddy with the pinned `caddy-dns/alidns` module.
- Adds an optional HTTPS listener controlled by `BAKER_HTTPS_ENABLED`, `BAKER_HTTPS_HOST`, and `BAKER_HTTPS_PORT`.
- Uses Aliyun DNS-01 so certificate issuance and renewal do not require public port `80` or `443`.
- Persists Caddy ACME and certificate state under `/var/lib/baker/caddy`.
- Keeps Aliyun credentials in container environment placeholders rather than generated Caddy configuration.
- Documents FRP TCP forwarding from a nonstandard public HTTPS port to Baker's internal port `3443` while preserving independent TURN/SFU media routing.

## Operator Notes

- Publish `3443:3443/tcp` only when the optional HTTPS listener is enabled.
- Use a dedicated least-privilege Aliyun RAM access key, not a root-account key.
- Continue mounting `/var/lib/baker` so automatic certificate renewals survive container replacement.
- The FRP web proxy must use TCP mode so TLS reaches Baker unchanged. TURN and SFU mappings remain separate.
