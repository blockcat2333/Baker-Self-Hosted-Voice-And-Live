# Baker 1.1.5

## Summary

Baker 1.1.5 fixes a Gateway ownership race exposed by transient network loss or
relay restarts. A replacement WebSocket can now reclaim the user's existing
voice membership, and delayed cleanup from the old socket cannot delete media
state already restored by the new connection.

## Realtime Recovery

- Transfers a stale same-user voice membership to the replacement connection
  during same-channel rejoin.
- Keeps `VOICE_ALREADY_JOINED` for a duplicate join sent by the same active
  connection.
- Associates voice, livestream, and music cleanup with the connection that owns
  each record.
- Prevents a delayed stale-socket close from evicting replacement voice,
  livestream, or music state.
- Adds regression coverage for same-channel voice takeover and stale-close
  cleanup across all realtime room managers.

## Operations

- Documents a relay failure mode where an HTTP watchdog continues probing an
  entrypoint after it has moved to HTTPS.
- Requires operators to test the exact health request and observe several full
  monitor intervals before enabling restart automation.
- Keeps HTTPS/WSS, TURN, and SFU validation as independent checks for every
  regional hostname.

## Upgrade And Compatibility

- No database migration is required.
- Replace the image while preserving `/var/lib/baker`, mounts, environment,
  restart policy, certificates, and every TURN/SFU/HTTPS port binding.
- 1.1.4 Web and Desktop clients remain compatible and gain the server-side
  stale-connection takeover fix after the server is upgraded.
- Roll back by recreating the container with the previous fixed image and the
  same persistent data and runtime configuration.
