# Baker 1.0.10beta

## Summary

Baker 1.0.10beta is a server/all-in-one beta focused on public IP automation reliability and deployment clarity. Public deployment docs now assume the all-in-one Supervisor container, and public IP detection includes endpoints that are more likely to work from mainland China server networks.

## Changes

- Added default public IP check endpoints:
  - `https://ip.3322.net`
  - `https://myip.ipip.net`
  - `https://ifconfig.co/ip`
  - existing `api.ipify.org`, `ifconfig.me`, and `checkip.amazonaws.com` remain as fallbacks
- Public IP response parsing now accepts plain IP text, JSON with an `ip` field, and localized text that contains an IP address.
- `BAKER_PUBLIC_IP_ENDPOINTS` is now documented as the operator override for server networks that cannot reach the default check endpoints.
- Fixed the all-in-one watchdog public IP apply path by importing `rename` before writing `runtime.env`.
- Public IP automation no longer marks a detected IP as fully applied when Media/TURN Supervisor restarts fail.
- Later public IP checks retry pending Media/TURN restarts after a previous restart failure.
- Admin Docker Hub update discovery now includes compact beta tags such as `1.0.10beta`.
- Deployment docs now state that public deployments should use the all-in-one Supervisor image. Split-service deployments must provide their own process supervision and restart hooks.
- Release metadata was bumped to server label `1.0.10beta`, with package metadata stored as semver `1.0.10-beta`.

## Images And Tags

- Server GitHub Release tag: `v1.0.10beta`
- Docker image tags:
  - `blockcat233/baker:1.0.10beta`
  - `blockcat233/baker:latest`
- GitHub Release source archives are attached automatically by GitHub for the release tag.
- No desktop installer is published for this beta; the current desktop/client label remains `1.0.9a`.

## Deployment Notes

- No database migration is required.
- Public deployments should use `blockcat233/baker:1.0.10beta` or `latest` as a single all-in-one container.
- Runtime repair, self-repair, deployment apply, and public IP automation service restarts require the all-in-one `supervisorctl` environment.
- If public IP checks fail from the server network, set `BAKER_PUBLIC_IP_ENDPOINTS` to a comma-separated list of reachable endpoints.
- The public IP automation still does not replace HTTPS, published media ports, TURN credentials, or SFU announced IP settings.
