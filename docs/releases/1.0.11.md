# Baker 1.0.11

## Summary

Baker 1.0.11 is a stable server/all-in-one release focused on true multi-region media routing. Deployments can now serve mainland and overseas users through different public hosts while returning region-specific TURN and SFU candidates for voice, music share, and livestream sessions.

## Changes

- Added `MEDIA_REGION_PROFILES` for host-based media routing.
- Gateway now selects a media region from the WebSocket request host and carries that `mediaRegionId` into voice, music share, livestream publishing, and livestream watching sessions.
- Media now builds ICE servers and mediasoup SFU transports from the selected region profile.
- Unknown media region ids are rejected instead of silently falling back to the default route.
- Region profile validation now rejects duplicate ids, duplicate hosts, invalid SFU port ranges, and ports outside the valid TCP/UDP range.
- The admin deployment panel can edit `MEDIA_REGION_PROFILES` from **Deployment Settings -> Media Region Profiles JSON**.
- The all-in-one update helper preserves `MEDIA_REGION_PROFILES` and publishes every configured SFU RTC port range during container rebuilds.
- English, Chinese, beginner deployment, and architecture docs now document dual-region media, frp same-port forwarding, and Public IP Automation boundaries.

## Upgrade Notes

- Public all-in-one deployments should use `blockcat233/baker:1.0.11` or `latest`.
- For dual-region SFU over frp or another relay, every announced RTC port must be reachable at the same public port number. A mapping such as `23335 -> 50000` will not work for SFU candidates.
- Public IP Automation continues to manage only the legacy global TURN/SFU values. Multi-region profile addresses are operator-managed static routes.
- After editing media region profiles in the admin panel, click **Apply And Restart Container** so the all-in-one container publishes any newly required ports.
